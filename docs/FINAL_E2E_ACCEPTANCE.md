# KRISHNA Final End-to-End Acceptance
KRISHNA is called fully operational only after all of these pass on the target PC/phone:
1. Windows artifact installs and Core starts.
2. Android app pairs with the intended PC and stores its approved credential securely.
3. Mobile conversation reaches the PC Core and reconnect/resume does not duplicate commands.
4. Registered-project failure is detected, investigated and reproduced.
5. Repair occurs in shadow, verification passes, promotion occurs, post-promotion checks pass; otherwise rollback restores the prior files.
6. A verified completion event reaches the mobile device.
7. Local STT/TTS providers are installed and a voice round trip succeeds.
8. Avatar GLB reports a skeleton, required animations and facial/lip morph targets and renders them.
9. Private remote route is configured and no unauthenticated public control port is exposed.
10. GNN training is permitted only when a validated schema, local backend and sufficient verified examples exist.

Repository code can enforce and test these boundaries, but hardware, models, network routes and avatar assets must be present on the target devices for physical acceptance.
